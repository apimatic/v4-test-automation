# Portal build fixtures

The APIMatic customer builds the visual tests generate portals from. Each folder
here is one build, registered in `config/portals.ts` and generated by
`scripts/serve-portal.mts`.

## Why these are vendored

They're copies of builds that also live in the portal repo, at
`apps/docs/test-specs/customer-build/`. Keeping our own copy means **a failing
snapshot always means the portal changed** — never that someone on the portal
team edited a build file underneath us. The tests own their inputs.

It also keeps this repo standing on its own: the fixtures are committed here, and
`.portal/` is a throwaway checkout that `pnpm setup:portal` can recreate at any
time.

The cost is duplication: refreshing a build is a manual step (below). Watch the
size — a build carrying sample media and SDK zips can run to several MB.

## What a build contains

Taking `petstore/` as the example:

| Path | What it drives |
|---|---|
| `APIMATIC-BUILD.json` | Branding, theme (base theme, colours, fonts), the language configs, `apiCopilotConfig` |
| `content/toc.yml` | The sidebar and the top-level sections |
| `content/**/*.md` | Hand-authored pages, e.g. `why-apimatic/what-apimatic-offers.md` |
| `spec/openapi.json` | The OpenAPI spec — source of the endpoint and model pages |
| `static/` | Logos, favicon, SDK zips |

Change any of these and the generated portal changes, so **editing a build is
editing a test fixture**: expect snapshots to shift and review the diff.

## Adding a build

```bash
cp -r .portal/apps/docs/test-specs/customer-build/<name> test-builds/<name>
```

Then add an entry to `config/portals.ts` with its routes, and a spec folder under
`tests/visual/<name>/`. Generate it once and browse the output to find the real
routes — don't guess slugs:

```bash
PORTAL=<name> npm run portal:serve
```

## Refreshing a build

Pulling in upstream changes to a build is deliberate, because it will move
baselines:

```bash
# 1. See what actually changed first
diff -r test-builds/petstore .portal/apps/docs/test-specs/customer-build/petstore

# 2. Take the new copy
rm -rf test-builds/petstore
cp -r .portal/apps/docs/test-specs/customer-build/petstore test-builds/petstore

# 3. Re-baseline, then LOOK at the new PNGs before committing
npm run test:visual:update
```

Commit the build change and the new baselines together, so the diff shows why
the pixels moved.
